# 怪物猎人集会码 · AstrBot 移植版

移植自 [padoru233/nonebot-plugin-mhcodes](https://github.com/padoru233/nonebot-plugin-mhcodes)，
原始源码基线为 `fe8c0efb57b8f7a30f912e1d049d221b6745611f`。遵循原项目 MIT 许可证，保留版权声明。
官方模板仅用于确认目录与 API 结构，未复制其 AGPL 模板实现。

## 功能

| 群聊命令 | 说明 |
| --- | --- |
| `/mh角色 猎人` | 登记或修改你在本群的角色名 |
| `/mh武器 太刀` | 登记或修改你在本群的常用武器 |
| `/mh添加集会码 ABC123` | 添加集会码，关联登记人并记录登记时间 |
| `/mh查看集会码` | 显示你的资料，以及本群所有集会码、角色、武器、登记人和时间 |
| `/mh删除集会码 ABC123` | 按完整内容删除 |
| `/mh删除序号 1` | 删除当前列表中的第 1 条；列表变化后需重新查看编号 |
| `/mh重置集会码` | 手动清空本群集会码，保留角色和武器资料 |
| `/mh帮助` | 查看命令说明 |

所有群员可添加、删除和清空；无需 @；不验证集会码的游戏格式，允许内容包含空格。
入口统一为 `/mh`，命令与具体输入之间必须有空格，例如 `/mh角色 猎人`。
也支持 `/mh 角色 猎人` 等前缀后有空格的写法；`/mh角色猎人`、`/mh武器太刀` 等连写不再匹配。
原中文裸命令、`i猎人` 和 `/w太刀` 不再匹配。仅响应完整命令，不响应聊天里的提及或私聊。
角色、武器按平台实例、群和用户隔离；修改资料后列表展示最新资料。每天自动清空或手动重置都保留个人资料。
重复添加同一码不更改登记人和登记时间；时间固定显示为北京时间（UTC+8）。
登记时间仅供人工判断，插件没有游戏服务查询接口，不能自动确认房间是否失效。

示例角色名“猎人”取自 [官方角色介绍](https://www.playstation.com/zh-hans-hk/games/monster-hunter-wilds/)
对玩家主角的称呼；这不是对创建角色界面预填姓名的确认。角色命令仍接受你实际使用的任意名称。

入口采用群聊过滤器和正则监听，参数前要求空格，`/mh` 与中文子命令之间的空格可选。
因此各入口不会作为标准指令出现在 WebUI 的指令管理中；权限沿用原插件的群员权限。
插件仍受 AstrBot 的插件启用状态、会话服务和配置文件插件选择影响。

## 配置

通过 WebUI 插件卡片的配置入口修改，保存后重载插件。

| 字段 | 默认值 | 行为 |
| --- | --- | --- |
| `daily_reset_enabled` | `false` | 可选每天自动清空所有群；默认关闭 |
| `reset_hour` | `4` | 重置小时，范围 0–23 |

登记时间显示和每日清空都固定使用北京时间，不依赖容器时区，不再提供 `timezone` 设置。

启用每日清空后，后台每分钟检查一次，到点后的空闲群将在一分钟内清空；任何命令都会先检查到期重置。
停机或禁用期间错过的重置，会在再次加载或操作时补做。每天重置不主动发送群消息。
时钟回退不重复清空。改变重置小时或重新开启自动清空可能改变有效周期，操作前备份数据。
旧安装已经保存为 `true` 的配置不会因默认值变化自动关闭；更新时请在 WebUI 明确关闭。

## 安装与数据

目标 API 基线为 AstrBot `>=4.16,<5`，该版本 AstrBot 本体要求 Python 3.12 及以上。
当前支持声明为 QQ OneBot v11（`aiocqhttp`）；其他平台未完成验证。
本插件无额外运行依赖；北京时间直接使用标准库固定 UTC+8 偏移。

将发布安装 ZIP 通过 AstrBot WebUI 插件管理上传安装；或者将此目录放到
AstrBot 的 `data/plugins/astrbot_plugin_mhcodes`，通过插件管理加载或重载。
运行依赖由插件管理器根据 `requirements.txt` 安装。不要为本插件默认重启整个 AstrBot。

持久化文件为 AstrBot 数据目录下的：

```text
data/plugin_data/astrbot_plugin_mhcodes/mh_codes.json
```

群数据按平台实例 ID 与群 ID 共同隔离。读写事务使用异步锁并在线程中执行，采用临时文件原子替换。
读取损坏数据时明确报错并保留原文件，不自动清空或覆盖。
仅支持单个 AstrBot 进程管理同一数据文件，不支持多个进程共用该文件。

1.1.x 使用数据格式 v2。读取本插件 1.0.0 的合法 v1 数据时，先保存
`mh_codes.json.v1.<唯一标识>.bak`，再原子升级；旧记录登记人和时间显示未知，不编造日期。
回退到 1.0.0 前需停用插件并恢复 v1 备份；升级后的新登记信息无法由旧版读取。

移植版仓库为 [allenx555/astrbot_plugin_mhcodes](https://github.com/allenx555/astrbot_plugin_mhcodes)。
可以通过 AstrBot 插件管理使用此仓库地址安装和更新；插件市场提交前仍需完成真实环境测试。

旧 NoneBot 的 `mh_codes.json` 不能直接覆盖新文件：旧格式只有群号，缺少平台实例和重置日期。
本次未搬运任何生产数据。如果要导入，应先备份、停用插件，显式指定平台实例并转换格式。
回滚时关闭插件，保留配置和持久化数据即可；无自动修改其他插件或 AstrBot 主配置的操作。

## 本地开发

```powershell
cd D:\git\astrbot_plugin_mhcodes
uv run --no-project --with pytest python -m pytest -q
uv run --no-project --with ruff ruff check .
uv run --no-project --with ruff ruff format --check .
```

单元测试覆盖群/平台隔离、增删查重置、并发写入、4 点边界、停机补重置、损坏数据保护、
原子写入失败、取消事务和重载任务清理。入口单元测试使用 API 替身，不等于真实 AstrBot 加载或 QQ 收发成功。
详细开发依据和验证结果见 [DEVELOPMENT.md](DEVELOPMENT.md)。

1.1.2 本地已通过 42 项单元测试和 AstrBot 4.16.0 的真实 API 冒烟检查。
真实 API 检查没有启动完整服务或连接 QQ，尚未验证实际平台发送。

上线后分别检查：插件加载日志；在真实 QQ 群执行四条命令；跨群隔离；重载后不重复执行后台任务。
不能用容器启动、HTTP 200 或单元测试通过替代真实 QQ 功能验证。
